## Phase 2 — Download pipeline
Done when the API downloads a selected set of tracks into a folder with live progress, cancel and retry, all tested against the fake engine.

- [x] Download argv builder per format (MP3 320 CBR default, M4A copy, WAV, FLAC, original); yt-dlp writes only into a per-job temp dir. `downloadArgs` in `engine/ytdlp-args.ts`: yt-dlp only downloads the selected stream (no `-x`) into `<dataDir>/jobs/<attemptId>`, and finalize converts (ADR-015). Selectors: YouTube `ba`, SoundCloud `ba[acodec!=opus]/ba`, other `ba/b`; M4A tries `ba[ext=m4a]` first.
  - SoundCloud format narrowing: none. Default formats, and resolve's `audioSource` skips SoundCloud's Opus like the selector, so the source shown is the one downloaded (ADR-017, settling ADR-014).
  - `--extractor-retries 0` for SoundCloud, not `1`, which still retries once (from yt-dlp's source). Retries are bounded (`--retries 3 --fragment-retries 3`), and `--abort-on-unavailable-fragments` stops HLS from skipping a failed fragment silently
- [x] Parse progress (`DL`/`PP` lines, fragments for HLS, enforced "waiting" sleeps) and the final `DONE` JSON. `engine/ytdlp-progress.ts`: the percent comes from fragments first (HLS byte estimates jumped 4.3 % → 0.08 % → 29.8 % live) and never goes back within an attempt; a `before_dl` `START` print gives `available_at` → `progress.waitingUntil`, since quiet mode prints nothing while yt-dlp waits; a `START` with `playlist_id` or a second `START` stops the run as a list. 20 recorded cases in `fixtures/downloads/` (yt-dlp 2026.08.19), each with a meta-tested summary row
- [x] Extend `test/fake-yt-dlp.mjs` to replay downloads (`DL`/`PP`/`DONE` lines, a file in the job dir); the download error logs are already recorded in `fixtures/errors/` (ffmpeg-missing, postprocess-*, interrupted). Download rules (`download: '<case>'`) with `{JOBDIR}`/`{NOW+n}` placeholders and a strict download-argv check; the old `-x` logs keep a `WITHOUT_RULES` reason. Plus `test/fake-ffmpeg.mjs` (fake ffmpeg/ffprobe over the FAKEAUDIO files of `test/fake-media.mjs`, replaying `fixtures/ffprobe/`) and `writeFakeEngine`
- [x] Finalize: artist/title, tags (comment = source URL), AIFF + artwork via ffmpeg, filename template, sanitize, skip-if-exists, safe move (copy + unlink across volumes). `engine/finalize-plan.ts` (pure: tags, comment rule, codec plan, argv, readback checks), `engine/finalize.ts`, `engine/id3.ts` (our ID3v2.3 writer, since ffmpeg 8 can't write COMM), `filename.ts` in shared (180 UTF-16 units), `fs/folders.ts` and `fs/move.ts` (link, or copy + reservation; never `rename` onto a name). Every output is read back with ffprobe, because ffmpeg exits 0 on truncated input (ADR-015, ADR-016, ADR-018)
- [x] Job queue: concurrency limit, state machine, cancel (SIGINT to the process group → SIGKILL → delete job dir), retry, stale job dirs swept at startup. Shutdown aborts and awaits every run before closing. Engine groups survive a SIGKILLed server, so record each job's pgid and kill leftover groups at startup. `jobs/queue.ts`, `jobs/attempt.ts`, `jobs/bus.ts`, `shutdown.ts`: SIGKILL after 3 s, `cancelRequested` while a running job stops, bulk cancel/retry/clear as one event, at most 2,000 finished jobs kept. Instead of pgid records, `server.lock` (`O_EXLOCK`; a second server waits 9 s, then exits 1) makes a `ps` sweep for groups whose argv names `<dataDir>/jobs/<uuid>` safe, and `run.ts` now SIGKILLs every run's group at close (ADR-018)
- [x] Per-platform pacing and back-off (YouTube ~300 tracks/h without login, SoundCloud 429s); Go+ previews reported as `preview_only`. `pacing/gates.ts` and `pacing/token-bucket.ts` (the limiter's bucket, now shareable): YouTube 10 + one per 12 s; SoundCloud shares the enricher's bucket and leaves it 5 tokens; a cooldown of 60 s doubling to 10 min with strikes, a half-open restart and a requeue to the front; 3 own strikes fail a job (ADR-017).
  - YouTube pauses on `bot_check` too, and a bot check that reaches the 10-min cooldown twice in a row fails every queued YouTube job.
  - A ref marked `preview_only` (or any unavailable reason) fails at enqueue without a spawn; SoundCloud downloads also pass `--break-match-filters "format_id!*=preview"`, whose silent exit 101 maps to `preview_only`.
  - `resolve/limiter.ts` is reused for its token bucket only: the queue's gates need cooldowns and strikes the limiter doesn't have.
- [x] `GET /api/events` (SSE with heartbeat, throttled progress), `POST /api/downloads`, cancel, retry, reveal. A dropped SSE connection should also flip the engine chip to "Server offline": today it only notices on the next health request. Define `TrackRef` so a partial (not yet enriched) row can be downloaded. `routes/events.ts` (`retry: 1000`, snapshot first, a typed heartbeat every 15 s, no throttle since `--progress-delta 0.5` already caps progress lines), `routes/downloads.ts` (plus bulk routes and `GET /api/downloads` for tests), `TrackRef` with only platform, id and url required. Web: typed client calls, `lib/events.ts` feeding `['downloads']`, a drop past 2 s rechecks health, and the Vite proxy now ends a response the server cut off (ADR-019)
- [x] Settings store in the app data dir + `GET/PUT /api/settings`; native folder picker `POST /api/folders/pick`. `settings/store.ts` (field-wise repair, the bad file kept as `settings.json.bad`, atomic coalesced writes; a concurrency change resizes the queue), `fs/folder-picker.ts` (osascript `choose folder`, one at a time, 300 s), `fs/reveal.ts` (`open -R`)
- [x] `pnpm smoke --download [--format f]… [--keep] [--bare]`: the real pipeline against live YouTube and SoundCloud into a temp dir, each file read back with ffprobe and `test/id3-reader.ts`; `test/smoke-download.test.ts` runs it offline. The 2026-10-03 run matched the design for every case (YouTube to MP3, M4A, AIFF, original; a SoundCloud MP3 copied at 128 kbps without a comment; Go+ refused)

## Phase 3 — UI
Done when the full flow works in the browser: paste → (track: auto-download | playlist: select → download) → progress → files in Finder.

- [x] Paste anywhere / drop / type; instant platform + type badge; resolve on paste. `features/resolve/`: a document `paste` listener (not inside other text fields) plus a ⌘V/Ctrl+V fallback that focuses the link box, drop (`text/uri-list`, then `text/plain`), the first link in the pasted text; the badge from `classifyUrl` (DRM links refused without a resolve). `useResolve` is a `useMutation` per paste with its own AbortController: a new load aborts the running one, and so do Cancel, Esc and leaving the page; results are keyed by the paste's number (ADR-020). Every way in loads through the link box (Try again too), a refused paste clears a previous error so its Try again can't load the old link, and a dragged file is refused instead of replacing the app
- [x] Track card with immediate download and cancel. `features/track/`: `autoStart` waits for settings, is frozen at mount and false for an unavailable track, and queues once under StrictMode; the source shown becomes the job's once it reports one; `JobInline` (from `features/downloads/job-*`) shows the live status with one action at a time (Cancel, Retry, Reveal in Finder) and "Download again" when a retry can't help, the job left the list, or beside Retry when the job's folder went away (ADR-020). After a manual Download, Try again or Download again, focus moves to the card's download area, so Tab reaches the job's action
- [x] Collection view: header, virtualized track table, select all/none/invert, shift-click ranges, filter, unavailable rows disabled, progressive fill-in for SoundCloud sets. `features/collection/`: header counts ("50 of 214 tracks", "≈" totals), notes for the cap, skipped rows and `lists`; a 44 px div table with ARIA table roles and roving focus; a pure selection reducer over a `Set` of `platform:id` keys; a filter that ignores case and accents (and matches ø, æ, ß and the like by their plain spelling) and keeps the selection (ADR-021). Partial rows fill in through `useEnrichment` (ADR-022)
- [x] Download bar: target folder (header picker + recents), format, playlist-subfolder toggle, "Download N tracks". The header's `FolderPicker` (recent folders, "Choose folder…" with Cancel while the dialog is open, errors in a popover), `FormatSelect` (one line per format), the subfolder switch showing the sanitized name, and "Download N tracks" sending the selected rows in table order, each track once. The bar is sticky only on lg+, so below lg it never covers the focused row. Folder paths here, in the folder menu, the panel's batch rows and the track card are cut at their start (`FolderPath`), keeping the part that tells them apart
  - The folder is checked and read when it is chosen, in the dialog (`POST /api/folders/pick`) or from the recents (`PUT /api/settings`), so a macOS privacy prompt appears then rather than in the middle of a batch: `checkPickedFolder` (ADR-024).
- [x] Downloads panel: per-track and overall progress, waiting state, cancel/retry, reveal in Finder. `features/downloads/`: `JobRow` and `JobInline` share `job-text.ts` (output next to source, copied or re-encoded, waiting and requeued states) and `job-actions.ts`; the panel is one virtualized list of batch headers and job rows, bulk actions for all or one batch through one mutation, queue notes for pauses (announced) and paced starts (shown only), and counts spoken at most every 3 s. Overall progress covers the batches at work since the panel was last idle, so it moves back only when a new batch arrives (`use-running-summary.ts`; `summary.ts`: downloading 0–0.9, processing 0.9, finished 1)
  - `['downloads']` is read only through `useDownloads`, `useJob`, `useJobIdsByTrack` and `useQueue`; no mutation writes into it (ADR-019). A collection row's chip reads its job by id, so a job's progress re-renders that chip alone.
  - `useCreateDownloads` invalidates `['settings']` on success, since the server adds the folder to `recentFolders`.
  - No step waits for a 100 % progress event, and a job's artist falls back to its uploader.
- [x] "This track or the whole playlist?" prompt for watch+list URLs. Word it by `collectionKind`, and default to the track for a mix ("Load the mix (first 50)"). If the track lookup fails (private, age-restricted…), still offer the list with `mode: 'collection'`. "This track" reuses the track in the answer, with no second resolve
- [x] Loading state for big lists: a 1,788-video channel took 21 s and 5,001 rows up to 56 s. If that proves annoying, stream rows with `--lazy-playlist -j` (ADR-013). A skeleton shaped like the guess; after 3 s the elapsed seconds, and for lists "Big lists take a while: 1,800 videos ≈ 20 s, 5,000 ≈ 1 min."; Cancel throughout
- [x] SoundCloud `/sets` and `/albums` user tabs resolve to empty collections (only `skippedEntries`): let the user open those sets. `Collection.lists` links the skipped rows that are lists (any platform: a YouTube channel's Playlists tab too), and the header opens one with a resolve (ADR-023); new fixture `soundcloud/user-albums.json`
- [x] Partial rows: request enrichment for the rows in view, cancel requests for rows scrolled away, and show placeholders while SoundCloud's budget paces a long scroll. `use-enrichment.ts` over `enrich-session.ts`, outside TanStack Query: 150 ms debounce, the shown rows plus 5 on each side (never a row the filter hides), 4 rows per request and 2 in flight, failed rows asked again after 30 s and then less and less often (up to every 10 min), nothing while the tab is hidden (ADR-022)
- [x] Engine missing/outdated banner and friendly error states. `EngineBanner`: server offline with the start command, engine problems with their install or upgrade command and "Check again", warnings dismissible for the session; `lib/error-text.ts` gives each error code a next step under the server's message
- [x] Playwright e2e for both flows against the fake engine. 10 spec files, 25 tests per browser (Chromium, WebKit): single track (⌘V pressed for real too), playlist (and the focused row kept clear of the sticky header below lg), watch+list and mix prompts, resolve states, cancel, the SoundCloud set, the downloads panel, the folder, the engine banner and the shell
  - `test/e2e-server.ts` runs `writeFakeEngine` (`FAKE_YTDLP_VERSION` from `todaysYtdlpVersion`) with e2e rules of its own: a download per playlist row, set row 6 by its API URL, a slow list, a hanging download and a private track in a playlist. `e2e/fake-urls.ts` lists the URLs.
  - The console guard stays strict: a spec expects each "Failed to load resource" line with `expectConsoleError(failedLoad(status, path))`, and a test fails if an expected line never comes.
- [x] Export the shared test helpers (`testUuid`, `youtubeRef`, `soundcloudRowRef`, `testBatch`, `jobsByStatus` in `src/test-helpers.ts`) as a package subpath. Done in Phase 2's review fixes: `@dj-scraper/shared/test-helpers`, used by the server and web tests; a Biome `noRestrictedImports` rule keeps it out of runtime code
- [x] "Original" YouTube downloads fetch a thumbnail that their WebM can't hold (`--write-thumbnail` is passed for every format but WAV). Skip it when the original will be WebM, or say in the UI that "original" has no artwork. `canHoldCover(format, platform)`: no thumbnail for WAV or a YouTube original; SoundCloud's MP3 or AAC original keeps its cover, and `FormatSelect`'s Original line says a YouTube original has no artwork (ADR-015 amendment)

## Phase 4 — DJ polish
- [ ] Settings page (format, filename template, artwork, concurrency, auto-download singles, sign-ins)
- [ ] Artist/title clean-up rules ("Official Video", "[HD]", "Lyrics", …) with preview
- [ ] Already-downloaded detection (download archive) with badges in the track list. Until then, downloading a known playlist again downloads every track again (each ends `skipped` at publish) and spends the platform's pacing budget. The track table's job chips (from `useJobIdsByTrack`) cover only the jobs the server still holds
- [ ] Persistent download history
- [ ] Optional sign-ins, per platform and opt-in: browser cookies for age-restricted YouTube, SoundCloud login for originals and Go+ (never passed in argv)
- [ ] Keyboard shortcuts (paste, select all, download, cancel). ⌘V anywhere and the track table's arrow keys exist since Phase 3
- [ ] A full data drive (`disk_full` from yt-dlp, ffmpeg or the job dir) fails only the jobs that hit it, plus the queued jobs for the same target folder. Decide whether it should fail or pause every queued job instead, since they all need the data drive
- [ ] Share rate-limit cooldowns between enrichment and downloads. They share SoundCloud's token bucket, but a 429 pauses only the side that saw it (ADR-017)
- [ ] Stall detection, if hangs show up in practice. Retry sleeps and forced waits print nothing in quiet mode, so a no-output timer must allow for them (`waitingUntil`). Today only the 20 s socket timeout and cancel bound a download
- [ ] Check in rekordbox, Serato and Traktor that they read our tags: the COMM frame in MP3, the trailing `ID3 ` chunk (tags and cover) in AIFF, FLAC's `DESCRIPTION` comment, and titles with combining characters (tags keep the platform's text; only file names are NFC)
- [ ] `JobOutput` has no bit depth, so a FLAC output can't say "16-bit" (PCM's depth comes from the codec name, e.g. `pcm_s16be`). Add `bitDepth`, read back with ffprobe, so FLAC is as honest as AIFF. The UI doesn't show `sampleRateHz` yet either
- [ ] A YouTube "original" that turns out to be AAC (no Opus offered; none seen live) becomes an M4A without a cover: the thumbnail is skipped before yt-dlp picks the stream, and yt-dlp has no per-format thumbnail option (ADR-015 amendment). Revisit if one shows up
- [ ] Read the folder at enqueue too (`POST /api/downloads`), as `checkPickedFolder` does when a folder is chosen (ADR-024): a folder whose privacy access was revoked after it was chosen would then fail with 422 before any job exists, instead of each job failing at publish
- [ ] Check the macOS privacy prompt live: pick `~/Desktop` or a USB drive while the terminal app has no Files and Folders permission, then answer Allow or Don't Allow (422 with the privacy message). Tests script the filesystem and never see a real prompt
- [ ] Check paste anywhere in a real Safari/WebKit: ⌘V with nothing focused and an Edit-menu paste (e2e dispatches a `paste` event), and the drop overlay when a link is dragged in from another window or the drag is canceled with Esc
- [ ] While the server is down under `pnpm start`, the browser's EventSource reconnects by itself every second (the server's `retry: 1000`) and logs a console error each time. Consider closing it on error and reconnecting with our own back-off, as already happens after Vite's 502 (ADR-019)
- [ ] SoundCloud set rows 2–5 (`the-royal-concept-ep`) have no recorded lookups or downloads, so the fake engine answers `unsupported_url` for them: the e2e set spec sees them as "Couldn't load details", and only row 6 can download. Record them (fixture work) so the whole set flow runs; `SOUNDCLOUD_USER`'s rows can't be looked up either
- [ ] Finalize refusals that will always repeat ("original" can't be kept, WAV/AIFF over 4 GB, not an audio file, no audio) are `postprocess_failed`, so Retry and "Retry failed" run them again and fail the same way, and their messages suggest another format while a job can't change it. Give them a non-retryable code or flag (shared contract, server, an ADR) and word them for a job
- [ ] Track card: "Adding to downloads…" and the first "Queued…" mount with their text already in their status region, so screen readers may not announce them. Keep one status region mounted from the request to the job. Focus also stays on the card's download area when the job's action appears
- [ ] A failed job without an action (age-restricted, login required, Go+ preview) has its next step only as screen-reader text in its row; sighted keyboard users can't reach the hint without a new tab stop per row
- [ ] Drag and drop: the full-window "Drop the link to load it" overlay still covers another text field (the filter) while plain text is dragged over it; a drag that carries both a file and a link (an image inside a link) is refused as a file; a refused drop says nothing beyond the not-allowed cursor
- [ ] `test/e2e-server.test.ts` and `test/boot.test.ts` time out (about 4 s) starting a server when the machine is heavily loaded (load average about 18, parallel agent runs). Consider a longer startup budget if it shows up again
